# 代码规范与兼容性约定

## 1. 总原则

- 优先做局部、可追踪的修改。先定位实际调用者和状态生命周期，再修改实现；不要顺手重排无关代码。
- 保留 Minecraft 1.7.10、Java 8、LWJGL 2.9.1 的兼容性。不要把 LWJGL 3 API、Java 9 以上语法或依赖新版 JDK 的类加入现有路径。
- 新代码沿用所在文件的缩进、命名和括号风格。现有反编译方法名可保留；给新增字段和辅助方法使用表达用途的名称，避免再造含糊的编号名。
- 源码和文档使用 UTF-8。不要把机器绝对路径、玩家账号、访问令牌或完整日志写入仓库。
- 保持一个行为只有一处权威状态；跨界面传递必要数据，避免从已清除的全局状态猜测上一次目标。

## 2. 设置与 Profile

CheatBreaker Settings 属于 `GlobalSettings.settingsList`，写入游戏目录下 `config/client/global.cfg`。模组设置属于 `AbstractModule` 的设置列表，写入当前 Profile 的 `config/client/profiles/<名称>.cfg`。新增选项时：

1. 使用现有 `Setting` 注册入口，提供明确且稳定的标签和类型对应的默认值。枚举型字符串用 `acceptedValues(...)`；数值型设置用 `setMinMax(...)`。
2. 模组内同一配置区的可持久化标签必须唯一。不要以临时变量替代 `Setting`，也不要把模组开关放进 `GlobalSettings` 仅为省事。
3. 确认旧配置缺少新键时回到模块默认值，而不是沿用前一个 Profile 的值。切换 Profile、关闭游戏、重启后都应得到一致状态。
4. 模组缩放、锚点、坐标、启用状态与 HUD 显示状态和普通 `Setting` 一起保存；GUI 中改变这些值时走既有保存时机。
5. 通过 `ConfigValueCodec` 统一解析全局配置和 Profile 的数值、范围与允许值。读取无效值时保留合理默认值；不要在两个读取分支写不同的解析规则。
6. 读取配置不得覆盖原文件。写入使用同目录临时文件再替换目标文件，以免中途失败造成空文件。

改变配置格式或解析逻辑时扩展现有 `ConfigValueCodecTest`；发布脚本会运行该检查。配置的默认值、旧文件兼容性、生效时机和持久化目标都属于功能的一部分。

## 3. GUI 与网络状态

- 新按钮沿用已有 `GuiButton` 的尺寸、居中方式、文字风格和间距；按钮的绘制、启用状态与点击命中区域要对应。对多个入口使用同一交互时，逐一检查普通服务器、置顶服务器、直连等路径。
- 一次点击只触发一次动作。切换界面后不要再让旧界面消费同一批剩余事件；需要时在新 tick 处理。
- 连接、登录、超时、游戏中断线是不同路径。若失败界面需要重连地址，应在 `loadWorld(null)` 或其他清理操作前保存并显式传递；没有可用地址时不能假装已经具备重连能力。
- 网络线程与客户端 GUI 线程的职责要清楚；不要在绘制函数里执行 DNS、网络连接或长时间 I/O。失败与取消要能回到正确的上级界面。
- 连接中、下载地形和连接失败界面共享 CheatBreaker 的黑色渐变背景时，调用现有 `drawConnectionBackground()`，避免局部界面退回泥土背景或出现两种不同灰度。
- 布局应适应不同 Gui Scale 和分辨率；新控件不能遮住错误说明或退出入口。

## 4. 键盘、输入法与鼠标

- 只有 `Minecraft.runTick()` 消费 LWJGL 的 `Keyboard.next()` 队列。读取事件时记录 `currentScreen`，随后只交给游戏或该 GUI 一方。`GuiScreen.handleInput()` 只处理鼠标队列。
- GUI 的 `handleKeyboardInput()` 处理本界面的字符、快捷键和一次全局快捷键调用。不要把同一次按下再交给游戏循环，避免 Esc、F5、F11 等被重复触发。
- `PhysicalKeyboard`、`KeyboardPressTracker` 负责物理按键边沿。Esc 持续按住只算一次；松开再按应恢复。必须保留字符重复输入以及 `key == 0` 的输入法提交事件。
- 聊天和其他真正输入文字的 GUI 中维持原版禁止移动规则。中文或日文输入法处于激活状态但没有文字焦点时，不应阻断移动或弹出选词框。
- `Modern Keybind Handling` 仅控制关闭 GUI 后是否立即恢复仍按住的游戏按键；它不允许在 GUI 内移动，也不关闭 Esc 去重与输入法兼容逻辑。
- Windows Raw Mouse Input、IME、无边框全屏的 JNA/Win32 调用要检查平台与失败返回值，保存并恢复被修改的系统状态；非适用平台保留原 LWJGL 2 路径。

涉及键盘队列、焦点或快捷键路由的修改，按 `AGENTS.md` 运行 `python tools/check_keyboard_routing.py`。脚本检查结构和部分按键状态；实际 IME 候选框、鼠标方向、F11 切换仍需在 Windows 游戏内观察。

## 5. 编译与打包边界

- 相互依赖的 Java 文件在同一次 `compile_changed.ps1 -Sources @(...)` 调用中编译，避免拿旧 `.class` 解决新源码的引用。
- 新编译的顶层类、匿名类和内部类全部登记在 `tools/build_release.py` 的 `overlay`。新增类时先查看 `target/rebuild-classes/` 中实际文件名，再核对打包清单。
- `target/rebuild-classes/` 会保留历史产物。只打包明确登记的类，不能以整个目录覆盖基础 JAR。
- “编译通过”“打包通过”“已安装”“游戏内验证”是不同结论。给用户报告结果时写明完成到哪一层；修改游戏行为后不能只编译就宣称玩家已可使用。
- 发布到本机版本目录要检查 `CheatBreaker.json`，比较构建与安装 JAR 的 SHA-256，并提醒玩家完全退出游戏后重新启动。

## 6. 修改完成时的检查顺序

1. 查看 `git diff`，确认改动集中且没有覆盖原有输入、全屏或 UI 逻辑。
2. 检查配置项的默认值和保存目标，检查 GUI 的所有入口与状态清理分支。
3. 编译本次修改的 Java 文件；若要交付可运行版本，维护 `overlay` 并执行打包安装流程。
4. 如涉及输入或配置解析，运行对应既有检查；如涉及平台 UI，记录是否做过真实游戏内操作。
5. 查看 `git diff --check` 和 `git status --short`。仅在任务要求时提交 Git，并在报告中给出明确的构建与安装状态。
